# SkiSense — プロジェクト詳細（日本語）

> これは SkiSense の詳細ドキュメントである。入口は
> [README_ja.md](../README_ja.md)（日本語）/ [README.md](../README.md)（英語）。

スキー滑走映像から滑走者の姿勢を推定・可視化し、フォームを定量的に評価するコンピュータビジョンツールである。

## 開発の背景

本プロジェクトの開発者は幼少期からスキーを続けており、大学ではスキーサークルに所属し **基礎スキー**（フォームの美しさと技術点を競う競技種目）に取り組んでいる。基礎スキーには一定の採点基準が存在するものの、最終的な点数は審判の主観に委ねられる部分が大きく、滑走者自身が客観的に自己評価を行う手段は限られている。一方、日本ではスキー滑走映像を分析・可視化するツールは普及しておらず、競技者が日常的に利用できる環境は整っていない。

### 当初の目的とその断念

当初は **大量の滑走データと検定点数の組合せを学習させ、AI が自動採点を行うツール** を目指していた。しかし、以下の制約が実用レベルでの達成を阻むことが判明した。

- 映像からは斜度が判断できない
- 雪面状況（硬さ・湿り気・凹凸）は実際に滑走しなければ評価できない
- 検定基準を再現するには学習データの質・量ともに不足している

### 方針転換と現在の成果

以上の検証結果を踏まえ、プロジェクトのスコープを **「自動採点」から「姿勢の可視化と定量評価」に再定義** した。現在の SkiSense は、関節角度を数値で示し、理想的な範囲との乖離を色分けで提示する可視化ツールとして機能している。

Meta SAM 3D Body により、人体メッシュと推定3D関節座標を取得する処理を導入した。膝・股関節・足首の推定角度を扱える一方、斜め視点・遮蔽時の推定誤差や競技技術との対応は未検証である。数値は姿勢把握の補助とし、真の関節角度や技術の客観的評価として断定しない（詳細は[スコア仕様](spec/pose-scoring.md)）。

**開発期間:** 2026 年 1 月開始、継続改善中。

## 主な機能

- **人物検出** — YOLOv8x によるスキーヤー検出
- **骨格推定** — 既定は YOLO26-Pose（2D COCO-17）。YOLO11-Pose または Meta SAM 3D Body（MHR由来の推定3D関節座標・人体メッシュ）にも実行ごとに切替可能
- **関節角度評価** — YOLO では膝・股関節を 2D、SAM 3D Body では膝・股関節・足首を 3D で算出。肩の水平傾きは 2D 画面平面で評価
- **総合スコア** — 算出可能な項目を 0〜100 点で評価
- **複数人トラッキング** — Deep SORT によるフレーム間の ID 一貫性
- **自動ズーム・センタリング** — 胴体中心を画面中央に固定し、人物 bbox 面積が画面の約 35% になるよう動的ズーム
- **ベストショット抽出** — 最高スコアのフレームを自動保存

## 実行モード

通常モードでは、YOLOv8x による人物検出、Deep SORT による追跡、選択された backend による ROI 単位の骨格推定を順に実行する。追跡の安定性を優先する標準経路である。

```bash
python run.py video.mp4
```

高速モードでは、`--fast` を付ける。YOLO11/YOLO26は全画面の人物・キーポイント検出を実行し、複数人物の候補を返す。SAM 3D Bodyでは専用人物検出器を無効にしているため、現状は画像全体の単一bboxで推論し、複数人の認識・対応付けは保証できない（[Issue #16](https://github.com/kmch4n/SkiSense/issues/16)）。両者とも毎フレームのYOLOv8x＋Deep SORT処理を省略するが、`longest`かつズーム有効時は主対象を決めるための事前走査を行う。

```bash
python run.py --fast video.mp4
```

高速モードの出力動画は `video_pose_fast.mp4` として保存される。

高速モードでフレームごとに最大面積の姿勢検出bboxを選択する場合は、`largest` を指定する（SAM3Dは単一の全画面bboxにフォールバックするため、人物を比較選択する機能にはならない）。

```bash
python run.py --fast --target-mode largest video.mp4
```

従来の 2D パイプラインを再現する場合は `--pose-backend yolo11`、
3D の体と足先を推定する場合は `--pose-backend sam3d` を指定する。
CUDA 非搭載機では既定の `yolo26` または `yolo11` を利用できる。

```bash
python run.py --pose-backend yolo11 video.mp4
python run.py --pose-backend yolo11 skier.jpg --image
python run.py --pose-backend sam3d video.mp4
```

## ズーム仕様

ズーム有効時は、肩中点と腰中点の中間を **胴体中心** として扱い、この点ができるだけ画面中央に来るように crop する。倍率は固定値ではなく、対象スキーヤーの bbox 面積が出力フレーム面積の約 35% になるよう自動計算する。対象が画面端にいる場合は、元映像外を複製せず、crop を元フレーム内に収めて実ピクセルを優先する。

```bash
SKISENSE_ZOOM_TARGET_AREA_RATIO=0.35
SKISENSE_ZOOM_MAX_SCALE=5.0
SKISENSE_TARGET_SELECTION_MODE=longest
```

`SKISENSE_TARGET_SELECTION_MODE=longest` は原則として最長出演trackを主対象にする設定だが、現行コードでは**ズーム有効時のみ**YOLOv8x＋Deep SORTで事前走査する。通常モードではそのtrackのbboxにROI姿勢推定結果を対応付け、`--fast`では対応する全画面推論結果を選択する。ズームを無効にすると事前走査は行われず、対象人物の選択仕様も変わる（[Issue #15](https://github.com/kmch4n/SkiSense/issues/15)）。ズーム状態では対象が検出されない間、最後の位置を短時間保持し、その後中央・等倍へ戻る。

通常のズーム有効モードでは、検出・追跡は複数人に対して行い、選択した主対象だけのbbox・骨格・スコアパネルを描画する。ズーム無効時の通常動画では、現行コードにbbox・骨格描画が欠落する不具合がある（#15）。高速SAM3Dについては複数人検出の保証がない（#16）。

`SKISENSE_TARGET_SELECTION_MODE=largest`または`--target-mode largest`は事前走査を行わない。**通常モード＋ズーム有効**では、いったん選んだconfirmed track IDを優先し、選び直す際に最大面積のtrackを選ぶ。一方、**高速モード**では毎フレーム最大面積の姿勢検出bboxを選ぶ。ズーム無効時は対象選択と描画の既知不整合がある（#15）。

## 技術スタック

| 技術 | 役割 | 採用理由 |
|------|------|---------|
| [YOLOv8x](https://github.com/ultralytics/ultralytics) | 人物検出 | 高精度で複数人シーンでも安定。Ultralytics が公開する学習済みモデルを使用 |
| [YOLO26-Pose](https://docs.ultralytics.com/models/yolo26/) | 骨格推定（既定） | 2D COCO-17 キーポイント。公開重みを使い、CPU / MPS / CUDA に対応 |
| [YOLO11-Pose](https://docs.ultralytics.com/tasks/pose/) | 骨格推定（従来の 2D 出力） | 2D COCO-17 キーポイント。以前の出力を再現する場合に選択 |
| [SAM 3D Body](https://github.com/facebookresearch/sam-3d-body) | 骨格・人体メッシュ推定 | Meta の単一画像 3D 人体メッシュ復元モデル（2025-11-19 公開）。MHR パラメトリックモデルにより 3D 関節角度を提供 |
| [Deep SORT](https://github.com/nwojke/deep_sort) | トラッキング | フレーム間で検出された人物に一貫した ID を付与 |
| [OpenCV](https://opencv.org/) | 動画入出力・描画 | 業界標準の CV ライブラリ |
| [PyTorch](https://pytorch.org/) | DL バックエンド | CUDA / MPS / CPU の統一 API（SAM 3D Body は CUDA 必須） |
| python-dotenv | 設定管理 | 設定値をコードから分離し、環境別の切替を容易にする |

### 姿勢推定バックエンドの選択

SkiSense は姿勢推定エンジンを実行ごとに `--pose-backend` で、恒久的には `.env` の `SKISENSE_POSE_BACKEND` で切り替えられる。優先順位は CLI フラグ → `.env` → 既定値 `yolo26` である。

```bash
python run.py --pose-backend sam3d video.mp4    # この実行のみ 3D エンジン

SKISENSE_POSE_BACKEND=yolo26   # 必要に応じて yolo11 または sam3d に変更
```

YOLO11-Pose は以前の 2D 出力との比較用に残している。YOLO26 と YOLO11 は足首角度を評価せず**最大5項目**、`sam3d` は**最大7項目**の平均になる。キーポイントの欠損によって採点項目数がさらに減る場合がある。2Dと推定3Dでは角度の定義が違うため、モデルをまたいでスコアを比較しないこと。

各モデルの特性・設定・使い分けの詳細は [`pose_backends_ja.md`](pose_backends_ja.md) を参照。

- **YOLO26-Pose（既定）**: COCO-17 を 2D で推定。`yolo26x-pose.pt` が初回に自動ダウンロードされる。足先ランドマークがないため足首角度は `N/A`。
- **SAM 3D Body**: MHRトポロジの足先ランドマークを使って足首角度（knee→ankle→big-toe）も採点する。膝・股関節・足首は推定3Dカメラ座標から算出し、2Dの投影歪みを直接用いないが、深度復元や遮蔽の誤差は残る。重みはHugging Faceのゲート公開で、初回にアクセス申請と`hf auth login`が必要（[セットアップ](sam3d_setup.md)）。
- **YOLO11-Pose**: COCO-17 を 2D で推定。`yolo11x-pose.pt` が初回に自動ダウンロードされる。足先ランドマークがないため足首角度は `N/A`。

肩の水平傾きは「映像上の傾き」を表す指標として、どの backend でも 2D 画面平面で計算している。

## アーキテクチャ

### 処理パイプライン（フレーム単位）

フレーム単位で以下の 3 ステップを順に実行する。

1. **検出・トラッキング** — YOLOv8 で人物を検出し、Deep SORT により持続的な ID を割り当てる
2. **骨格推定** — 通常モードでは検出領域（ROI）のbboxを各バックエンドに渡す。SAM 3D BodyならMHR由来の先頭63点（3D＋2D投影）とメッシュ、YOLO11/YOLO26-PoseならCOCO-17の2Dキーポイントを取得する。高速モードではモデル固有の全画面処理を使用する（SAM3Dの単一bbox制約は#16）。
3. **描画** — ZoomTracker によるズーム変換を適用し、骨格線と bbox を描画、最後に情報パネル（スコア・角度）を重ねる

### モジュール構成

- **`config.py`** — `.env` から全設定を読み込み、型変換とバリデーションを行う
- **`pose_topology.py`** — MHR由来の先頭63点（SAM 3D Body）とCOCO-17（YOLO11/YOLO26-Pose）の2トポロジを定義する。`is_3d`フラグで`pose_analyzer`が推定3D/画像2Dを切り替える。なおUIの「MHR-21」は要素数ではない。
- **`backends/`** — 姿勢推定 backend。YOLO26-Pose、YOLO11-Pose、SAM 3D Body を選択でき、`get_backend(backend=...)` が CLI フラグ → `SKISENSE_POSE_BACKEND` → 既定値の順で解決する。`PoseBackend` ABC により将来の backend 追加にも備える
- **`pose_analyzer.py`** — 純粋関数による関節角度の計算と評価。副作用・I/O なし
- **`zoom_tracker.py`** — 対象bboxの面積から動的ズーム倍率を算出し、画面内に収まるようcropする。現行実装では検出対象の中心・倍率を即時反映し、見失った場合は30フレームまで最後の対象状態を保持する。
- **`main.py`** — オーケストレーション。デバイス解決、backend 取得、フレームループ、動画 I/O
- **`image_processor.py`** — 静止画向けの単発解析フロー

### デバイス解決ロジック

`auto` モード時の優先順位は **MPS > CUDA > CPU**。ただしコンポーネントごとに制約が異なる。

- **YOLOv8x** は CUDA / MPS / CPU に対応、CUDA 時のみ `half=True`、MPS では `half=False`
- **SAM 3D Body** は CUDA 必須。`device_str` が `cuda` 以外のとき backend は起動時に例外を投げ、`--pose-backend yolo26` への切り替えを案内する
- **YOLO11/YOLO26-Pose** は CUDA / MPS / CPU いずれでも動作する
- **Deep SORT** は MPS 非対応のため、macOS でも CPU フォールバック

## 姿勢評価ロジック

`pose_analyzer.py` は以下の関節角度を評価する。閾値は現行コードのヒューリスティックな設定であり、競技審判や運動科学に基づく実証的な妥当性は未検証である。測定定義と既知の問題は [`spec/pose-scoring.md`](spec/pose-scoring.md) にまとめる。

| 評価項目 | Good | Caution | Fix |
|---------|------|---------|-----|
| 膝屈曲角（左右、YOLOは2D / SAM3Dは3D） | 90°〜120° | 80°〜90° / 120°〜140° | それ以外 |
| 股関節角度（左右、YOLOは2D / SAM3Dは3D） | 100°〜130° | 90°〜100° / 130°〜150° | それ以外 |
| 足首角度（左右、SAM3Dの3Dのみ） | 70°〜90° | 90°〜110° | それ以外 |
| 肩の水平傾き（2D） | ±10° 以内 | ±20° 以内 | それ以上 |

### スコア化

各項目をGood=100／Caution=50／Fix=0で評価し、可視性を満たす項目の平均を整数化して**0〜100点**の総合スコアとする。YOLOのキーポイント信頼度が閾値未満の項目は平均から除外される。一方SAM3Dは関節ごとのvisibilityを実測せず、利用する関節には原則1.0を割り当てるため、遮蔽の不確実性が評価に反映されない。

SAM 3D BodyのMHRトポロジは足先ランドマークを含むため、足首角度をknee→ankle→big-toeの3点で算出している。ただしこれはブーツへの前圧を直接測定した値ではなく、単眼画像に基づく推定姿勢の代理指標である。

### ドメイン知識の反映

- **前傾姿勢** の参考指標として肩・股関節・膝のなす角度を使う。脊柱の湾曲や足圧そのものを測定しているわけではない
- **肩の水平維持** は画像上の左右肩線の角度を用いた暫定指標。方向角の折り返し欠陥（#12）とカメラ傾斜の影響がある
- **膝の屈曲** は股関節・膝・足首の3点角度で近似する。実際の荷重や雪面反力を直接測定していない

## 開発で苦労したこと

### 1. 当初目的からの方針転換

AI 自動採点という当初目的は、映像単体では取得できない情報（斜度・雪面状況）と学習データの制約により達成困難であった。プロジェクトを完走させることを優先して妥協した機能を実装するよりも、**スコープそのものを再定義して確実に価値を出す** 判断に切り替えた。結果として、自己練習ツールとしての実用価値を獲得し、副次的ではあるが自身の技術向上という具体的な成果に結びついている。

### 2. 座標変換の 3 段階管理

滑走者を画面中央に追尾するためのズーム機能を後から追加した際、座標系の混乱が発生した。フレーム上の点は以下の 3 つの座標系で扱われる。

1. **ROI 座標** — 検出された人物の bbox 内部の相対座標
2. **フレーム座標** — 動画全体の絶対座標
3. **ズーム座標** — 拡大・中心調整後の最終出力座標

当初はズーム係数を各描画処理に散らばせて適用していたため、ランドマーク・bbox・情報パネル間で微妙な位置ずれが発生し、デバッグに苦しんだ。最終的には **`transform_point_to_zoom()`** に変換を一元化し、全ての座標は必ずこの関数を通過させる設計に改めた。これにより描画のずれは解消し、保守性も向上した。

### 3. スキー姿勢に強い骨格推定への移行

滑走映像は、深い内傾、内脚の遮蔽、スキー板やストックの干渉、雪面反射などにより、一般的な 2D 人物姿勢推定ではキーポイントが不安定になりやすい。途中段階では YOLO11-Pose（COCO-17）への移行で安定性を稼いだが、依然として 2D 投影歪みにより視点依存のスコア変動が残り、足先ランドマークを失ったことで足首角度評価ができない欠陥もあった。

その後、Meta SAM 3D Body を導入した。3D メッシュ＋MHR キーポイントにより、3D の関節角度（knee / hip / ankle）が得られ、足先（big-toe・small-toe・heel）も復帰した。ただし CUDA とゲート重みが必要である。現在は導入しやすい YOLO26-Pose を既定とし、3D の推定が必要なときに SAM 3D Body を選べるようにしている。両者の出力を同じ映像で見比べる機能も加えた。

## 今後の改善予定

- **One-Euro フィルタ** による時間的スムージングの導入（3D キーポイント座標のフレーム間ジッター低減）
- **メッシュ／法線ベース可視化** — SAM 3D Body の `pred_vertices` を活用した立体的なオーバーレイ
- **MHR `shape_params` を用いた身長正規化スコア** — 体格差を吸収した相対評価
- **自前データセットによるファインチューニング** — 基礎スキー特化のフォーム評価精度向上
